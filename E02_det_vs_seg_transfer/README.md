# E02_det_vs_seg_transfer: do E01's detect-vs-segment results transfer to cell microscopy?

A class ML sub-experiment of JANNUS / BrainMetScan, following `..\E01_det_vs_seg`. It is **not**
part of the 1.X release line and produces **no 1.60 artifacts**. Data: LIVECell (phase-contrast
cell microscopy, 8 cell lines), not patient data.

**Status: CLOSED 2026-11-18.** Pre-registered and approved 2026-11-16 (`PREREG.md`, deviations
D1 and D2). All arms trained for 250 epochs; the test set was predicted once on 2026-11-18. The
reports are final.

## Result in one paragraph

E01's findings did not transfer as general rules, because they depend on objects being well
separated. On LIVECell, the nnU-Net segmenter (A) segments well (image Dice 0.906), but reading
it out as one point per connected component fails: touching cells merge, giving 32 components per
image against 304 cells, so A's detection CPM is 0.093. The heatmap detector (B) reaches 0.943.
The two-stage arms had nothing to fix: the primary contrast (C1 vs. B) could gain at most about
0.0065 CPM and gained 0.003.

| Hypothesis (from E01) | Contrast | Point [95% CI] | Outcome |
|---|---|---|---|
| H1 | B−A CPM | +0.849 [0.801, 0.890] | not replicated (B better) |
| H2 | A−B sens@1FP, large cells | −0.894 | not replicated |
| H3 | B−A CPM, small cells | +0.776 [0.614, 0.812] | replicated, 8 of 8 lines |
| **H4 (primary)** | C1−B CPM | +0.003 [0.000, 0.004] | not replicated (5 of 8 lines) |
| H5 | C1−A image Dice | +7.2e-06 | replicated (C1's mask is A's) |
| H6 | C4−A object Dice | −0.015 [−0.026, −0.006] | not replicated (0 of 8 lines) |

CIs: cluster bootstrap over the 9 test wells (2,000 resamples, seed 20261116).

## Assessment (close-out review, 2026-11-18)

- **Execution: strong.** Pre-registered, one test prediction, deviations hash-logged,
  well-clustered bootstrap, cross-GPU check, self-checking report generator.
- **Design: weaker.**
  - H4 could not succeed: C1 only re-scores B's points, and B's FROC curve is already at its
    0.949 ceiling. A training-set ceiling check before approval would have caught this.
  - Arm A, semantic segmentation with connected-component readout, is known to fail on touching
    cells. It tested the readout as much as segmentation.
  - The one-hit rule does not count B's duplicate points (about 1.9 per detected cell) as false
    positives, so B's numbers are optimistic.
  - With only 9 wells, small effects cannot be resolved.
- **Main lesson:** detect vs. segment depends on how crowded the objects are. Segment-then-count
  is only safe when objects rarely touch.

## Possible follow-ups (not started)

- An instance-aware segmentation arm (watershed on A, or a Cellpose-style flow model).
- One-to-one (Hungarian) matching as a secondary scoring rule.
- A reader review of B's top false-positive images, for unannotated cells.
- More wells or a second seed for the small effects (H4, H6).

## How it was run

Every command is `env\run.cmd -m e02.<module> [args]`, using
`G:\BrainMetShare\1.60_artifacts\venv-1.60` read-only.

| Step | Module |
|---|---|
| Build Dataset921 and instance maps from the download | `setup_dataset` (`--verify-only` re-checks) |
| Training-set statistics → pixel parameters (`params.py`) | `train_stats` |
| nnU-Net plan and preprocessing | `plan_preprocess` |
| C2 crop dataset (training images only) | `c2 --build`, then `c2 --preprocess` |
| Training (A, B, C2 in sequence, 3070 Ti) | `jobqueue` via `env\resume.cmd`; one arm: `launch_train --arm A\|B\|C2` |
| Test prediction and evaluation (both GPUs) | `run_eval --cases test` via `env\eval.cmd` |
| Data report and figures | `write_data_md` |
| Tests | `env\run.cmd -m pytest -q -p no:cacheprovider code`: 80 pass; the 3 trainer-integration tests skip until `plan_preprocess` is re-run |

Other modules: `common` (paths, GPU selection), `params` (fixed parameters), `decode` (maps →
points), `heatmap`, `loss`, `trainers`, `trainer_heatmap` (models), `two_stage` (C1/C2/C4
rules), `predict`, `c2_predict` (inference), `evaluate` (matching and endpoints), `pause`,
`control` (run control), `c2_bench`, `gpu_diff` (checks).

## Reproducibility notes

- nnU-Net v2.6.4, torch 2.10.0+cu128, cuDNN 91002. Inference: fp32 with TF32 convolutions,
  step 0.5, Gaussian weighting, mirroring.
- Runs are not bit-reproducible: cudnn.benchmark is on (as in E01), and the two GPUs differ
  slightly (max |Δp| 0.0008 for A, 0.0006 for B, 0.016 for C2 crops). No assigned C2 value
  changed. Which GPU predicted each test image is in the worker logs
  `results\eval\worker_pred_<arm>_<n>_<gpu>.log`; code hashes per run are in `run_log.jsonl`.
- **Deleted at close-out (2026-11-18, about 10.3 GB, all regenerable or temporary):**
  - `data\nnUNet_preprocessed\` (both datasets, 8.6 GB). To train again, rebuild it with
    `plan_preprocess` and `c2 --preprocess`. Inference does not need it.
  - The 2-epoch smoke models `E02SegTrainer_smoke` and `E02HeatmapTrainer_smoke` (1.4 GB). The
    `*_smoke` result folders remain as the record of those runs.
  - `results\tmp\` holding the C2 checkpoint used by `gpu_diff`, an epoch-39 snapshot. The
    comparison checked arithmetic, not model quality.
